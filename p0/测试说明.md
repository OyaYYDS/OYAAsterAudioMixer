# ASTER P0 验收测试说明

- 工具位置：`p0\AsterAudioP0.exe`（无需管理员权限）
- 日志位置：`p0\p0logs\`（两座位共用同一目录，每行自动带 `user` / `session` 前缀）

## 方式一（推荐）：交互菜单

**双击 `p0\AsterAudioP0.exe`** → 出现编号菜单，全程按提示输入即可：

```
1. 查看当前用户信息
2. 列出所有音频设备
3. 查找进程 PID
4. 设置进程的扬声器/麦克风   ← 输入进程名 → 选 pid（带"← 本座位"标记）→ 选方向 → 选设备
5. 查询进程的扬声器/麦克风
0. 退出
```

## 方式二：命令行（可选，进阶）

```
AsterAudioP0.exe whoami            # 确认当前座位的用户/会话
AsterAudioP0.exe list-devices      # 列出所有输出/输入设备（名称 + ID）
AsterAudioP0.exe find chrome       # 查 chrome 的 pid（可能有多个，注意 session 列）
AsterAudioP0.exe get <pid> render|capture
AsterAudioP0.exe set <pid> render|capture <设备名>
```

设备名支持三种写法：友好名（如 `"扬声器 (High Definition Audio Device)"`，带空格要加引号）、SWD ID、端点 ID。

## 准备

1. 两座位都登录各自账户，分别运行 `whoami`，确认 user 不同（座位A=____，座位B=____）
2. 各自运行 `list-devices`，选定两个**不同**的输出设备（用耳朵好分辨的）：
   - 座位A 的设备A：____
   - 座位B 的设备B：____
3. 测试期间**不要改动** ASTER 的每座位默认设备设置和 Windows 声音设置
4. 涉及 pid 时用 `find <进程名>` 获取，注意核对 session 列是否属于自己的座位

## 验收项（逐项执行；判定栏填 通过/失败）

### 1. 座位A 基础路由
- 座位A 打开 chrome，播放有声内容（视频）
- `find chrome` 取主进程 pid，`set <pid> render 设备A`
- 预期：声音立即切到设备A；`get <pid> render` 返回设备A 的端点 ID
- 实际：____ 判定：____

### 2. 座位B 基础路由
- 座位B 同样开 chrome，`set` 到设备B
- 预期：声音从设备B 出；`get` 返回设备B
- 实际：____ 判定：____

### 3. 【核心判据】座位A 新开窗口不串扰
- 座位A 再开一个 chrome 新窗口（新进程），播放声音
- 预期：声音仍在设备A；新进程 `get` 仍返回设备A，**不是**设备B
- 实际：____ 判定：____
- ❌ 若此项失败 → 说明"每应用持久化按 HKCU 每用户隔离"不成立，**立刻停止测试**，触发 PLAN.md 失败预案讨论

### 4. 座位A 重启持久化
- 座位A 完全退出 chrome（任务管理器确认进程全退）后重新启动
- 预期：不执行 `set` 也自动走设备A
- 实际：____ 判定：____

### 5. 麦克风方向（两座位同测）
- 两边各自打开同一个会用麦克风的程序（如录音机）
- 各自 `set <pid> capture` 各自的麦克风设备
- 预期：各用各的麦克风互不影响；`get <pid> capture` 返回各自设备
- 实际：____ 判定：____

### 6.（可选）重启系统后
- 重启后两座位重新登录，**不执行任何 set**，直接打开 chrome
- 预期：仍走各自的设备（持久化保留）
- 实际：____ 判定：____

## 判定规则

- "预期"与实际一致、且用耳朵验证过 → 通过
- `get` 返回 `S_OK (0x00000000)` 且 endpointId 为期望设备 → 通过
- 若 `set` 返回非 0：把完整 HRESULT（日志里已自动记录）连同当时程序状态（是否正在出声/刚启动）一起记录，继续后续步骤——这本身也是重要数据
